# 第一阶段架构边界

本阶段是渐进拆分，不是重写，也没有将正式小屋全面迁移到 Qt。现有插件 API、SQLite 数据键、Tk 入口及独立 Live2D 渲染进程继续保留。

## 已落地的服务

- `desktop_pet/services/state.py`：`AppState` 管理已持久化的专注模式与免打扰状态，不引用 Tk 或 Qt。`App.focused` 保留为 v1 插件兼容属性，生产宿主读写都转到此服务；不再维护另一份易失的专注状态。
- `desktop_pet/services/timer.py`：`TimerService` 负责开始、暂停、继续、停止、到期和完成事件，使用可注入时钟，可无图形环境测试。`plugins/productivity/plugin.py` 保留旧方法、菜单注册、文字命令与 UI，只把计时状态转换委托给服务。
- `desktop_pet/services/notifications.py`：`NotificationService` 负责历史记录、FIFO 待显示队列和免打扰判断；正式气泡窗口仍由 `App` 创建。角色台词、动作仍在 `App.notify` 装饰后交给服务，不冒充已经完全拆出的通知系统。
- `Store.write_batch`：在一个 SQLite 事务中写入相关设置和事件；序列化错误或 SQL 错误不会留下半次状态转换，不改变现有数据库 schema。

## 计时持久化与延迟操作

继续使用 `plugin.productivity.timer`，旧 JSON 无须迁移即可读取。新增 `plugin.productivity.timer_revision`，默认值为 0；每次计时转换递增一次。

计时、版本、专注状态以及到期时的 `focus_planned_minutes` 事件一起提交；提交成功后再同步兼容宿主属性。计时完成按原定到期日期记录计划分钟数，不将它解释为真实专注行为。跨睡眠/重启仍采用原有墙上时钟到期语义，暂停计时保存剩余秒数。

完成通知中的“休息 5 分钟”和“再专注 25 分钟”捕获完成版本。点击时服务检查当前是否已有计时、版本是否仍匹配。即使新计时已经停止，旧通知也不能再开启过期流程；重复点击不会覆盖当前计时。正常的菜单开始方法仍保留原有签名兼容性。

数据库完成提交与气泡显示不是跨进程事务：若提交之后、显示之前进程退出，完成事件仍正确保存，但本阶段不保证补发那条气泡。这是有意保留的可靠投递边界，不是完整的持久化通知 outbox。

## 通知规则

历史最多保留 100 条，只有持久化成功后才更新内存或入队。免打扰时只记历史，不排队；开启免打扰会清空已排队的气泡，正式 App 同时关闭正在显示的气泡，不会在退出免打扰后突然补弹一串旧提醒。真正出队时还会重查免打扰，兼容旧代码直接修改设置的情况。

历史记录是纯数据；气泡回调只存在内存中，不序列化，不在加载历史时自动执行。计划任务到期通知与角色闲聊的内容/样式分层仍需在后续继续完善。

## 刻意保留的耦合

- `PluginContext.app`、Tk Notebook 与 action registry v1 仍保留；待办、提醒、使用统计尚未全部服务化。
- `App` 仍负责窗口、托盘、热键、角色事件映射、渲染上下文与插件调度；不是只有启动/退出的空壳。
- 老插件仍可能直接调用 `Store`；本阶段只使计时服务成为内置计时路径的唯一写入入口，没有给第三方插件制造安全沙箱。
- Qt 小屋是独立预览，不接管正式宿主的事件循环或用户数据。正式迁移需通过界面评审、Windows DPI/多显示器验证，再增加真正的视图适配器。

## 回归

`python -m unittest discover -s tests -p test_services.py -v`

覆盖开始/重复开始、暂停跨睡眠、重启到期、旧格式、旧通知版本、重复通知按钮、原子事务失败回滚、通知写入失败、免打扰切换和通知历史边界。`test_core.py` 与 `test_live2d_behavior.py` 同时验证旧插件命令及角色联动接口。无图形回归不能替代 Windows 原生窗口、DPI、透明合成和真实睡眠/唤醒验收。
