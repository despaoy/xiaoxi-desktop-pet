# 测试基线与干净发布

## 1. 默认基线（不需要完整角色美术源）

在仓库根目录运行：

```sh
python -m unittest discover -s tests -v
node --test tests/js/behavior-controller.test.js
```

默认基线涵盖存储、插件、计时、导航、对话、帧调度、前端状态与发布保护。`test_companion.py` 的时间线单元测试使用小型固定动作数据，不再让缺少可选旧角色素材导致所有对话测试失败。真实角色包兼容性仍有独立测试，安装素材后会执行；错误的 JSON、动作或持续时间不会被跳过。

明确区分通过与未验证：

- 没有显示服务时，真实 Tk 控件测试会跳过；不是视觉验收通过。
- 缺少旧图片渲染依赖（cv2 / numpy / Pillow）时，旧渲染测试模块明确跳过。其他导入错误仍失败。
- 缺少旧角色包或 atlas 时，只跳过对应的真实素材集成测试。Live2D 正式版不依赖这个旧美术包，相关路径见 `RESOURCES.md`。
- JavaScript 测试需要 Node.js。Python 内的 JS 桥测试不能替代单独运行上面的 Node 命令。

旧图片模式发布前，应按 `requirements-motion.txt` 安装依赖、配置 `RESOURCES.md` 中的角色素材，重新运行全套测试，确认这些旧渲染集成项不再跳过。Windows 桌面发布还必须实际运行 Tk / Qt、验证 DPI 和窗口交互；无头测试不能代替它们。

## 2. 发布数据边界

开发者的 `data/` 包含个人数据库、日志和设置，绝不能作为运行资源复制。`build-desktop.ps1` 现在：

1. 在 PyInstaller 覆盖旧输出之前检查 `dist/XiaoXi`。若检测到数据目录、SQLite 文件及旁文件、运行日志或符号链接，则停止构建。
2. 不再复制仓库根目录的 `data/`。运行资源仍由 `XiaoXi.spec` 明确列出。
3. 构建后再次检查输出，失败时禁止声称构建完成或分发。
4. 首次运行由现有 `Store` 自动创建空数据库；不需要随包预置数据库。

保护脚本只读，不会帮你删除个人数据。若旧 `dist/XiaoXi` 已被用来运行桌宠，先退出应用，将整个旧输出目录移到安全备份位置，再构建；不要直接清空其中的 `data/`。

分发前可再次运行：

```sh
python tools/release_safety.py dist/XiaoXi --require-output
```

这是对已知本地数据路径、数据库痕迹和链接的防误打包检查，不是任意隐私内容扫描器。不要把私人文件改名放进资源或插件目录。打包后不要在待分发的目录中试运行，测试应用应复制到独立测试目录；否则首次运行生成的 `data/` 又会进入待分发目录。

本检查未证明 Windows 安装包能运行，也未验证真实美术资源或第三方依赖的完整性。发布时分别记录单元测试、资源检查、实际打包和 Windows 人工验收结果。
